# SFT 验收计划

> 文档状态：历史规划材料，已随当前工具和案例一并归档；其中“待完成”表示当时的计划状态，不等于当前代码状态。


## 先澄清目标

本项目的 SFT 首要目标是让模型稳定输出可解析格式，不等于已经提升风控预测能力。必须把“格式改善”和“任务效果改善”分开验收。

## 已有事实

- FinQA 50 步 SFT 已完成，8 卡，验证损失 `0.2701720893383026`。
- 针对四行输出协议又完成 20 步 SFT，验证损失 `0.22653627395629883`。
- SFT 后受控 GRPO rollout 中 `32/32` 输出格式合法、程序可执行；这证明 SFT 解决了进入可判分 RL 的格式前置问题。
- 金融风控基模与 SFT 的独立评测已归档于 `docs/finance_risk/results/`；结果显示 SFT 格式有效率为 100%，但破产类 Recall 为 0，因此不能声称 SFT 提升了金融任务能力。

## 风控任务验收

对 Taiwanese Bankruptcy 使用完全相同的测试集，比较：

| 指标 | Qwen 8B 基模 | 现有 SFT | 说明 |
|---|---:|---:|---|
| JSON/结构格式合法率 | 待测 | 待测 | 输出是否可解析 |
| 标签提取成功率 | 待测 | 待测 | 是否产生 HEALTHY/BANKRUPTCY |
| Accuracy | 待测 | 待测 | 只作辅助指标 |
| 正类 Recall | 待测 | 待测 | 重点关注漏报 |
| Precision | 待测 | 待测 | 观察误报 |
| F1 / F2 | 待测 | 待测 | F2 更重视漏报时单独说明 |
| False Negative | 待测 | 待测 | 风控核心错误 |
| 平均响应长度 | 待测 | 待测 | 观察格式/冗余变化 |

## 执行顺序

1. 确认使用的 Qwen 8B 基模路径、版本和 thinking 配置。
2. 用同一测试集分别生成基模和现有 SFT 输出。
3. 使用独立解析器统计格式、标签和证据引用，不使用训练 Reward 代替评测。
4. 输出混淆矩阵、错误样例和指标表。
5. 若 SFT 只改善格式而未改善预测，不继续无依据增加 SFT 步数。

## 验收判定

- **格式验收通过**：合法率达到预设阈值且错误可追溯。
- **能力验收通过**：SFT 相比基模在独立指标上有明确改善，且不是只靠类别比例。
- **无法判定**：资源不足、输出无法加载或测试集不一致；必须记录阻塞项，不补造结果。
