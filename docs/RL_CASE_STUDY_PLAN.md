# 金融风控 RL 诊断与优化案例计划

> 文档状态：历史规划材料，已随当前工具和案例一并归档；其中“待完成”表示当时的计划状态，不等于当前代码状态。


## 1. 案例目标

在同一份固定金融风控数据上，完整保留以下证据链：

1. SFT 检查点的独立测试结果。
2. 首轮 GRPO 的 rollout 原始输出、训练曲线、规则命中和失败结论。
3. 根据诊断结果选出的优化方法及其依据。
4. 只改变已声明变量后的第二轮训练。
5. 优化前后在同一测试集上的指标对比和典型样本。

案例成功的含义不是“训练跑通”，而是优化后的 RL 模型相对同一起点的 SFT 和首轮 RL，在固定测试集上取得可重复的业务指标提升。

## 2. 固定条件

- 数据集：UCI Taiwanese Bankruptcy 固定 train/dev/test 切分。
- 起点：同一个金融风控 SFT 检查点。
- 首版奖励：`credit_risk_outcome_v1`，正确为 1，错误或非法输出为 0。
- 测试集：保持自然正负比例，不参与 SFT、RL 或规则调参。
- 训练与评测必须使用完全相同的 tokenizer chat template；模板差异视为实验无效。
- 主指标：Recall、Precision、F1、F2、False Negative、混淆矩阵。
- 训练对比：记录 seed、学习率、group size、KL 系数、batch、step 和代码版本。

## 3. 实验阶段

### C0：SFT 基线

对 SFT 检查点执行确定性推理，保存完整预测、非法格式样本、假阴性样本和独立指标。它是后续 RL 是否有效的比较基准。

### C1：诊断型 GRPO

从 C0 的同一检查点启动短周期 GRPO，不预设“必须成功”。工具实时提取：

- 每个 prompt group 的 reward 均值、方差和正确样本数。
- 全对、全错、近全对、近全错和有区分度的 group 比例。
- 格式非法率、BANKRUPTCY/HEALTHY 输出占比、响应长度和截断情况。
- KL、gradient norm、clip ratio、entropy、policy loss 的趋势与异常 step。
- 触发的规则、触发证据、严重度和推荐处理动作。

### C2：冻结诊断结论

训练结束后先生成诊断报告，再决定下一步。每条优化建议必须引用具体 step、group 或曲线证据，并记录 `rule_id`、规则版本和优化方法版本。一次只选择一个主要变量，避免无法归因。

候选优化方法包括：

- 全错 group 过多：降低任务难度、调整训练采样或先补充对应 SFT 样本。
- 全对 group 过多：增加有效难例比例，避免 advantage 大量为零。
- reward 离散但格式稳定：调整 group size、采样温度或数据分层，不立即增加复合 reward。
- KL 或梯度震荡：降低学习率、加强 KL 约束或缩小更新批次。
- 假阴性集中：对训练集做可追溯的正类/难例采样优化，不改变自然分布测试集。

### C3：优化型 GRPO

从与 C1 相同的 SFT 检查点重新训练，除已声明的优化项外，保持数据、reward、训练步数和评测流程一致。工具继续输出相同的 rollout 与稳定性证据。

### C4：案例验收

至少满足以下条件，才写成“优化有效”案例：

- C3 在固定测试集上的 F2 或 Recall 高于 C0 和 C1。
- Precision 没有跌破预先声明的业务下限。
- 提升不是由非法输出处理或测试集泄漏造成。
- rollout 中对应异常规则的命中率下降，且梯度/KL 未出现新的严重异常。
- 至少补做一个不同 seed；无法复现时只记录为探索结果。

## 4. 沉淀材料

每个阶段保存但暂不提交 Git 的实验材料：

- `run_manifest.json`：模型、数据、算法、参数、seed 和版本。
- `predictions.jsonl`：固定测试集逐条预测。
- `metrics.json`：独立业务指标和混淆矩阵。
- `rollouts/*.jsonl`：原始 rollout、group_id、reward 和 reward components。
- `diagnosis.json`：规则命中、证据引用、推荐动作和采用/拒绝原因。
- `charts/`：reward 分布、group 结构、KL、梯度、clip ratio 和对比图。
- `case_report.md`：问题、证据、决策、修改、结果和限制。

Git 保存工具、规则、评测脚本、文档模板、可复现实验命令和标准化小型结果；大体积模型、完整日志、完整 rollout 和检查点继续保存在本地实验目录。

## 5. 当前原型进展

C1-C4 是实验阶段编号，不代表复合 Reward。当前案例使用的仍是纯结果 Reward；格式和证据来源只作为诊断信息记录，尚未加入训练总分。

已完成一次两步 NGRPO 检查点探索，形成了“发现 SFT 单类塌缩和 GRPO 同质组较多 -> 依据既有算法选择经验切换 NGRPO 并调整训练采样 -> 逐 step 保存并独立评测 -> 选择有效 checkpoint”的完整原型链路。

该原型证明工具能够帮助发现短暂的有效训练窗口，也证明仅看训练 reward 或 sampled rollout 不足以选择模型：候选 checkpoint 必须回到固定测试集做确定性评测。当前结果仍存在误报较高、第二步单类塌缩和缺少第二 seed 的问题，因此状态为“案例原型完成，业务验收未完成”。详细实验产物保存在本地案例目录，不提交 Git。
